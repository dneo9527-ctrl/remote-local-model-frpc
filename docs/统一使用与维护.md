# R-L AI 控制台 · 统一使用与维护

本项目统一维护 Windows 本地模型与 Windows Sub2API 两条连接，共用 Mac「本地 AI 控制台」和同一 GitHub 仓库。两条连接分别启停、分别验收，复用原程序与私人资料，不再开发另一套重复面板。

本说明优先于旧版 `使用说明.md` 及交接文件中的历史操作描述。账号、Key、frps 配套资料仍仅在各自机器保存。

## 两条连接

| 连接 | Windows 启动入口 | Mac 本机入口 | 使用客户端 |
| --- | --- | --- | --- |
| Ollama 本地模型 | 原「本地模型控制台」→ 一键启动 | `127.0.0.1:11435`，visitor 为 `11436` | Cherry Studio、网页聊天 |
| Sub2API 账号池 | 原部署的「启动 Sub2API」/ `Start-Sub2API.cmd` | `127.0.0.1:18081/v1`，STCP 目标 `sub2api_ke` | CC Switch → Codex |

Windows 的 Ollama provider 与 Docker `sub2api-frpc` 是独立服务。模型面板显示 Ollama 注册成功，不代表 Sub2API 已注册；Mac 本机 listener 开启也不代表远端 API 已连通。

## Mac 日常使用

1. 在 Windows 启动所需服务。使用 Ollama 时，等待原模型面板的一键启动完成；使用 Sub2API 时，确认其 Docker 项目和对应 frpc provider 正常运行。
2. 打开现有「2本地 AI 控制台.app」（本机安装在 `/Applications/RD/`），开启所需连接。无需每天重新配置 Key，关闭的另一条连接可保持关闭。
3. Ollama 使用 Cherry Studio 或网页聊天。Sub2API 接口验收通过后，在 CC Switch 的 Codex 分类选择 **Windows Sub2API**；模型使用网关实际支持的值，切换后按需重启 Codex并在新聊天验证。

连接设置默认展开，线路和操作按钮并排对齐；管理与维护默认折叠。再次打开 App 或菜单“打开控制台”唤回已有窗口，不新开浏览器页面。

`preview.5` 的“分层诊断”将本机监听、隧道、当前 frps 日志、health、认证和 Responses 分开显示。首页/菜单状态刷新不请求上游；健康、认证和最小模型调用逐项手动触发。检查结果显示时间，五分钟后或连接变化后标记过期，不能当作持续在线保证。Codex App 实际新聊天仍单独验收。

两张卡都连接同一台 Windows，分别对应 Ollama 与 Sub2API；VPS 是中转线路，不是另一台推理电脑。每张卡的“管理线路”可新增、编辑、复制、删除或导入配套的 STCP visitor。只有一条时直接显示名称，多条时下拉选择后再点应用；保存资料不会自动切线。使用中方案的修改另存为副本，待明确应用；不能删除使用中方案。

新增 VPS 最省事的方法是先在 Windows 配好对应 provider，复制该服务的 visitor 配置，再在 Mac 对应卡片的“管理线路”导入。也可手工填写 VPS 地址、控制端口、provider 名与配套隧道凭据。Ollama 和 Sub2API 的 provider 不同，须分别导入；本机端口保持 11436 和 18081，服务 API 地址不变。只改 VPS IP 不能保证连通，仍需两端注册、端口和凭据配套。新方案保存不等于实际连通，须手动检查。

编辑器不回显原有 token 或 STCP secret，留空保留。复制 visitor 配置会写入本机剪贴板，内容含隧道凭据，仅用于自己的接收设备，不含 Sub2API 下游 API Key。删除只移除未使用的方案登记，原私有文件与修改前备份保留。TLS 和 STCP 加密固定开启，新增文件仅保存在原本机工具的私有目录。

“使用中/待应用”会同时显示。同线路不重复切换，网页回答进行中拒绝切换其 Ollama 连接；其他客户端的生成状态无法由面板确认。网页聊天保存独立本机模型偏好；在原生窗口中返回控制台后再进聊天，会保留同一后端实例内的草稿、回答和流。分类日志就地打开摘要窗。

| 操作 | 实际效果 |
| --- | --- |
| 关闭窗口 / ⌘W | 隐藏窗口，后台和连接继续运行 |
| 最小化 / ⌘M | 最小化窗口，后台和连接继续运行 |
| 关闭某连接开关 | 仅停止对应本机连接 |
| **全部退出** / ⌘Q | 暂停本机 Ollama 网关与 visitor、停止 Sub2API visitor，再结束控制台和菜单；保留 Windows 服务和私人资料 |

全部退出后重开，连接开关保持关闭，需要时再显式开启；没有新加登录自启。换 VPS 前先结束正在生成的回答，两端必须使用已配套的节点、端口和认证。

## 已有验收与待办

- **Ollama 历史验收，2026-11-18：** STCP 和统一网关接口成功，模型列表发现 10 个模型；`qwen3-8b-8k:latest` 完成 Cherry 真实聊天及 211 事件流式回答并正常结束，报告上下文 8192。其他模型不能据此全部标为生成通过；这也不证明现在在线。
- **Mac 本地界面，2026-11-19：** 双连接、默认展开的新排版、菜单栏图标、单窗口复用、⌘W 和 ⌘M 已安装并核验；原生应用菜单全部退出已真实核对四个本机端口和所属进程结束。
- **Sub2API 远端仍待验收：** 最后一次 Mac health 请求对应 `sub2api_ke` listener 不存在。需核对 Windows 当前 Docker provider，随后依次完成 health、无 Key 拒绝/有 Key模型列表、实际支持模型的 Responses 流式请求。
- **CC Switch / Codex：** Windows Sub2API 供应商已保存；切为使用中、最终配置及 Codex App 新聊天尚未验收。不得用模型列表或登录状态代替真实对话。
- **后续独立范围：** 其他 VPS 双端实切、16K 性能、手机连接、Windows 真机更新、Apple 公证等仍按对应证据逐项验收。

Sub2API 的准确现场时间、Windows 需要执行的检查及认证约定见 [Mac Sub2API 交接](MAC_SUB2API_HANDOFF.md)。

## 维护与发布

统一仓库为 `dneo9527-ctrl/remote-local-model-frpc`。Mac 当前开发分支 `codex/mac-receiver`；Windows 来源分支 `windows`；公开发布由既有发布流程管理。两条链路的代码已在同一项目中，不为聊天整合重做代码合并、重启远端或重复发布。

旧聊天验收过公开版 `0.2.0-preview.1`。新候选 `0.2.0-preview.5` 集成 Windows `75c4435` 的 1.1.2 面板，Mac 新功能的本机验证与准确发布范围见 [验收说明](验收.md)。分支推送不能当成新 Release，公开下载以 Releases 的准确 tag、附件与校验值为准。

程序和长期资料在 `LocalTools` 原位置，源码与文档仍在本项目。私人配置、Key、CC Switch 数据库、原始日志及账号资料不进入仓库。旧文档和原服务不做批量删除或迁移。
