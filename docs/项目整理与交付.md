# 项目整理与交付

本仓库集中维护本地模型、FRP 连接、Mac 接收端及 Sub2API 扩展的源码。Windows 来源分支为 `windows`；无需为两个功能组维护两份源码克隆。

| 目录 | 用途 | 入口 |
| --- | --- | --- |
| `windows/local-model-console/` | Windows 原生 WPF 模型与 FRP 控制面板 | 依该目录 README 构建后运行 |
| `windows/sub2api-local/` | Sub2API、数据库、Redis 与 frpc 的 Docker 项目 | `Start-Sub2API.cmd` |
| `mac/console/` | Mac 接收端、连接管理与网页聊天 | 依 Mac README 启动 |
| `tools/` | 双端源码更新、构建及打包 | `launch.py`、`package_source.py` |
| `tests/`、各组件内的检查脚本 | 离线回归与原生 Windows 验证 | 依各组件验收说明执行 |

集中源码后，模型服务和 Sub2API 仍有各自的运行入口、配置与停止范围。打开模型面板不会自动启动 Docker；删除旧源码克隆不会卸载现有服务。现有部署保留在原安装位置，桌面快捷方式继续指向该部署。

## 私人设置与备份

仓库只保存示例配置，不上传实际 `frpc.toml`、`.env`、访问密钥、模型权重、Cherry Studio 会话、数据库、运行日志或私人连接包。访客配置复制文本包含连接凭据，应仅传给自己的设备。

源码包由 `source-files.json` 明确列出文件；不能直接压缩整个部署目录代替源码包。

```sh
python tools/package_source.py --out /absolute/path/to/delivery
```

输出为源码 ZIP 和 SHA256 校验文件。源码预览不等于 GitHub Release，分支提交不自动触发安装或服务重启。

## 清理规则

保留一份维护中的 Git 源码、当前部署、最新交付包和必要的恢复备份。旧克隆只有在工作区干净、提交历史已保留且不存在唯一的未跟踪文件时才可删除。旧原型或本地修改先保留紧凑源码快照。

已完成的测试夹具、字节码、构建产物和可重建依赖可以清理。迁移备份的解压副本须逐文件校验与保留 ZIP 相同，再删除解压副本。禁止沿目录链接递归清理；被运行进程引用或被锁定的内容跳过。

清理不删除模型权重、客户端数据、私有配置或 Docker 数据卷，也不按进程名称批量停止服务。

## 验证范围

Windows 模型面板 1.1.2 的既有验收记录包含原生回归及本机一轮启动、取消停止、确认停止。Sub2API 有独立的脚本回归与历史隧道验收。详细边界见各目录的验收文件。

源码整理仅验证文件、打包和版本历史保持完整，不代表 Mac、远端问答或当前 Docker 服务已重新通过运行验收。
