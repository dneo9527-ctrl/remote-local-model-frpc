# R-L AI 双端功能与边界

核对日期：2026-11-20。Windows 基线仍为 `75c4435b2736037cfecad9d80223071e1eb06817`；Mac 对应 `codex/mac-receiver` 本轮 `0.2.0-preview.6` 源码。本表按源码和本地隔离检查核对；安装、准确提交的 CI 与发布状态分别以[验收说明](验收.md)及后续实际记录为准。Windows 原生安装未由 Mac 操作；用户转来的 Windows 本机 TXT 路径不是本 Mac 可读取的文件。

## 功能对照

| 模块 | Windows 已有 | Mac 当前实现与边界 |
| --- | --- | --- |
| 服务启停 | 一键启动/停止、缺失组件补齐；Ollama 与 frp 独立停止；确认与错误提示 | 两业务连接独立开关；复用本机管理器。仅管理 Mac 网关/visitor，不控制 Windows GPU、Ollama serve 或 Docker。 |
| Sub2API | 原 `sub2api-local` Docker 四服务启停、桌面启动器、health、provider 注册检查、独立断隧道；保留账号池和数据库 | 独立卡片、visitor、线路管理、手动诊断和 CC Switch 入口。Windows 模型 WPF 面板与 Sub2API 仍是独立运行入口；Windows 同窗整合待做。 |
| VPS 线路 | 添加/编辑/删除、名称、自动国家/城市与国旗；Ping/TCP 分层检测 | 两条服务卡下方只有一个共用 VPS 节点区和管理入口。同地址/端口旧别名聚合为一行，显示自动地区、IP/端口及两业务各自使用状态；直接使用、编辑、检测、复制 IP。管理窗选中即编辑，支持新增、复制、删除、导入与按业务复制完整 visitor。新增继承两业务各自参数，高级端口、provider、凭据仍可编辑，空凭据保留且不回显。 |
| 保存与应用 | 普通切换仅改 `serverAddr`；保留其他配置；备份、冲突检查和失败恢复 | 直接保存原节点，不强制副本；保存不切线。“保存并使用”或首页“使用/应用”一次把 VPS 应用到 Ollama 与 Sub2API，保持各自原开关，关闭的业务不会被启动。失败时尝试恢复两路配置与原启停状态；检测到并发修改或恢复未完成会明确提示，保留后续修改；保留原节点快照。任一业务使用中的节点不能删除，网页生成时禁止切线。无法检测外部客户端是否在生成。 |
| 配置复制 | 所选线路完整 visitor 直接入剪贴板，不生成文件或切线 | 完整 visitor 复制到本机剪贴板，也可 TOML 导入；TLS/STCP 加密保持启用。剪贴板含隧道凭据，只私下传递；不含 Sub2API 下游 Key。 |
| 端口设置 | 可设置模型 API、frps、导出 visitor 端口及聊天地址 | 当前 Ollama visitor 严格固定 `11436`，网关 API 保持 `11435`；Sub2API visitor 固定 `18081`。尚无任意 visitor 端口与网关上游自动联动，不能仅放宽 TOML 校验。 |
| 模型 | 读取已安装模型、保存 Windows 项目默认模型，保留 4K/8K/16K 档案 | 从真实 Ollama 列表选择，保存独立网页默认模型；不覆盖 Windows、Cherry、CC Switch 或手机的选择。不负责远端模型下载/装卸。完整上下文/温度/最大输出高级设置页未完成。 |
| 网页聊天 | 提供网页入口；模型服务供远端客户端使用 | Ollama 文本流式、模型选择、推理内容显示、新对话与精确取消；最多发送最近 12 条消息。原生同一后端实例内保留草稿、回答与流；无持久聊天库、附件、自动压缩、知识库或聊天页 MCP。Sub2API 尚未接入聊天页，仅有最小诊断请求。 |
| 诊断和日志 | 进程/模型/隧道状态、日志和连接信息弹窗 | 节点检测显式执行 VPS Ping 与控制端口 TCP，分别显示成功/失败/超时及时间；五分钟后标过期，改 IP/端口不沿用旧结果。节点可达不证明 FRP 认证、provider 或模型 API 可用。首页/菜单被动状态；health、Key/models、最小 Responses 另行逐步手动执行，五分钟或连接变化后过期。分类日志只展示固定事件摘要，不暴露原始日志、节点、凭据或正文。 |
| 窗口与后台 | 浅色 WPF、状态卡、紧凑操作、Cherry/网页入口；关窗口保留服务 | 菜单栏图标、单窗口与两个保留的 WebView；紧凑节点管理窗口，原生确认框接收继续/取消。⌘W 隐藏/⌘M 最小化保留后台；全部退出停止本 App 管理的 Mac 连接、控制台和菜单。重开后连接保持关闭；无新增登录自启。 |
| Tailscale/手机 | 系统连接状态、查看/复制 IP；由系统客户端管理 | 未做手机接入自动配置或 Tailscale 私有转发，手机链路未验收。手机不能访问 Mac 的 `127.0.0.1`；Windows 回环服务需要明确私有转发，不能直接承诺 Tailscale IP:8080 可用。 |
| CC Switch/Codex | 已有本机成功链路须保留 | 由 CC Switch 管理供应商、Key、协议和模型；控制台不写旧 Codex 配置。Mac 的 Windows Sub2API 供应商已保存，使用中切换、最终配置及 Codex App 真实新聊天尚未验收。 |
| 源码与更新 | 同仓库 Windows 分支，白名单源码、SHA256、版本查询/暂存/选择/回退 | Mac 分支 `codex/mac-receiver`；本轮源码白名单为 140 项，包含节点检测模块及其测试。更新不会自动替换运行服务或私人资料；分支源码不代表已有对应 Release。Mac App 仅本机临时签名，无 Apple 公证。 |

## 连接约定

```text
Mac/其他客户端 → Mac Ollama API 网关 → visitor → VPS frps → Windows provider → Ollama
Mac CC Switch 配置的客户端 → visitor → VPS frps → Docker frpc → Sub2API → 上游账号池
```

其他设备访问 Mac 网关须另行配置可达且受保护的私有入口；上图不表示手机链路已实现。

| 用途 | 当前默认值 |
| --- | --- |
| Windows Ollama | `127.0.0.1:11434` |
| frps 控制端口 | TCP `7000` |
| Mac Ollama visitor / 网关 API | `127.0.0.1:11436` / `127.0.0.1:11435`，兼容入口 `/v1` |
| Mac 控制台 / 聊天 | `127.0.0.1:18765` / `/chat` |
| Windows Sub2API | 主机 `127.0.0.1:8080`；Docker provider 内部目标 `sub2api:8080` |
| Mac Sub2API | visitor `127.0.0.1:18081`；客户端 `http://127.0.0.1:18081/v1`，Responses |

同一台 Windows 可经不同 VPS 中转。相同端口、token、provider 和 STCP secret 配套时，Mac 新增或复制节点可沿用原参数，只改名称/VPS IP；Windows provider 也必须连接对应 VPS。高级参数保留编辑，TLS 与 STCP 加密保持启用。Mac 仅运行 frpc visitor；frps 校验和启动在目标 VPS 执行。Mac 之前两次 frps 校验被系统阻止后已停止，没有修改系统保护。

## 实测与待办

- **本轮本地检查：** 同 ID 编辑与应用、保存后待应用、运行状态保留、失败恢复和并发修改保护已做隔离回归。15 组离线浏览器检查通过、无页面错误，覆盖节点操作、检测缓存失效、草稿保护、真实浏览器剪贴板，以及桌面/720px/390px 布局；原生确认框另做隔离 WebKit/NSAlert 检查。这些检查不代表已在现有 App 完成全部按钮点按，不证明远端当前在线。完整本机安装与验收结果见[验收说明](验收.md)。
- **Ollama 历史成功：** 2026-11-18 的 8K 模型曾完成 Cherry 真实生成；不代表所有模型或当前连接都通过。
- **仍未当前验收：** 远端 Sub2API health、Key/models、Responses 流、CC Switch 使用中和 Codex App 真实新聊天；多 VPS 双端实切、手机、16K 性能、Windows 真机更新和长期后台。
- **实现优先项：** Windows 原面板纳入已有 Sub2API；双端完整线路档案兼容；如要改 Mac visitor 端口，同步网关、管理器、诊断和退出端口；随后再按需求做持久聊天、附件或高级模型设置，避免一次扩大范围。

日常最少步骤：Windows 启动所需服务 → Mac 打开现有 App 并开启所需连接 → 使用 Cherry/网页，或在接口验收后通过 CC Switch 选择 Windows Sub2API。换 VPS 时，编辑或新增节点后点“保存并使用”，也可先保存再从首页点“使用/应用”；须与 Windows 配套。停止所有 Mac 连接用“全部退出”。
